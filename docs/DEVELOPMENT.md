# Разработка и сборка

```bash
make test
make bundle REPOSITORY=AlexZhilov/lang-switcher
```

Сборка создаёт:

```text
dist/lang-switcher.tar.gz
dist/lang-switcher.tar.gz.sha256
```

Python wheels скачиваются в игнорируемую папку `wheels/`, в Git не попадают.
При уже подготовленном кеше можно собрать без сети:

```bash
python3 scripts/build_release.py --repo AlexZhilov/lang-switcher --no-download
```

`make test` не устанавливает программу и не меняет настройки рабочего стола:
проверки используют временные HOME и подставной backend GSettings. Проверяются
обновление старой установки, чужие сочетания, повторная установка, откат,
удаление и очистка временной папки bootstrap, включая ошибки загрузки.

В совместимом сеансе GNOME/X11 можно проверить Python-зависимости в одноразовом окружении,
без установки переключателя и без отправки нажатий:

```bash
python3 scripts/smoke_runtime.py
```

В `.github/workflows/` подготовлены тесты и публикация Release по тегу `v*`.
Перед публикацией выставьте `VERSION`, затем отправьте соответствующий Git-тег.
Workflow проверяет совпадение тега с VERSION, собирает комплект и прикладывает
его к GitHub Release. Источник команд Actions — официальные проекты
[checkout](https://github.com/actions/checkout),
[setup-python](https://github.com/actions/setup-python) и
[GitHub CLI](https://cli.github.com/manual/gh_release_create).

Исходный пользовательский переключатель был основан на модификации скрипта
Михаила Винакова. Эта версия сохраняет его поведение преобразования и добавляет
интеграцию GNOME, обработку ошибок и установку/обновление.

## Задержки обработки выделения

На горячем пути нет установщика и постоянного фонового Python-процесса:
обёртка запускает обработчик напрямую. Таблицы преобразования строятся при
импорте; смена языка идёт через D-Bus в GNOME, без имитации Alt+Shift.

Обработчик ждёт отпускания модификаторов (до 800 мс), затем проверяет буфер
каждые 5 мс до появления скопированного текста (до 600 мс). Время чтения
буфера добавляется к интервалу проверки. Единственная фиксированная пауза —
100 мс после Ctrl+V, до восстановления исходного текстового буфера. XSync
подтверждает обработку событий X-сервером, но не чтение буфера приложением.
Ранее суммарные обязательные паузы составляли 850 мс.

Тесты проверяют готовность копирования, отсутствие выделения, удержание обеих
сторон модификаторов, ошибки D-Bus/вставки и восстановление буфера. Для ручной
проверки в приложениях используйте латиницу/кириллицу, многострочный текст,
Ctrl+Shift+Q и заранее сохранённый текст в буфере. Скорость приложения и время
отпускания клавиш входят в фактическую задержку; автотесты без рабочего стола
не подтверждают время вставки во всех приложениях.

Клавиатура и буфер передаются операциям копирования/вставки явно; сохранение
буфера оборачивает всю операцию один раз. Код не отправляет Ctrl+V, если
преобразование не меняет текст. При частичном сбое X11 освобождаются все
клавиши, нажатие которых было предпринято, и выполняется синхронизация;
ошибка освобождения не скрывает исходную ошибку нажатия. Ошибка восстановления
буфера также не скрывает первоначальную причину сбоя; Ctrl+C возвращает 130.

Тестовый desktop backend моделирует и быстрое, и отложенное копирование
(включая задержку 400 мс), без отправки клавиш в пользовательские приложения.
Проверки ошибок используют настоящую последовательность обработки выделения,
а не подменяют сами операции копирования/вставки.
